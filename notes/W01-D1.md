## 2. 今天踩到的坑（原样记下来，别总结成体面话）

1. 中文 Windows 控制台是 GBK，脚本里打 emoji 直接 UnicodeEncodeError。
2. HEAD 请求 api.deepseek.com 返回 401 —— 这不是"网络不通"，是"没带钥匙"。
3. **`git push` 报 `Could not create directory '/c/Users/\316\342\263\277\317\243/.ssh'` + `Connection reset by ... port 22`**
   - 现象：`ssh -T git@github.com` 能成功，但 `git push` 失败。
   - 根因：机器上装了两套 ssh。系统 `C:\Windows\System32\OpenSSH\ssh.exe` 处理中文路径正常；Git 自带的 `D:\Git\usr\bin\ssh.exe`（MSYS 编译）把用户目录名解析成 GBK 八进制字节 `\316\342\263\277\317\243`（=吴晨希），建不出 `~/.ssh`，写不进 known_hosts，随后连接被重置。
   - 修复：`git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"`
   - 学到：**排障先分清"网络不通"和"程序自己坏了"**。`Connection reset` 看着像墙，其实是本机 ssh 处理不了非 ASCII 路径。
   - 面试怎么讲：这是典型的"环境问题伪装成网络问题"。定位手法是看报错的路径——出现乱码字节就说明是编码，不是连通性。
